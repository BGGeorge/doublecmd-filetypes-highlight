# Double Commander 文件类型高亮（扩展包）

按**文件扩展名/掩码**给文件面板里的**文件名**上色 —— 和 Total Commander 各种“按类型着色”修改版效果一致。
本项目是一个**独立扩展包**（与 Double Commander 官方项目无隶属关系）：不改动 DC 一行源码，只是把“文件类型颜色”规则写进 DC 自己的配置。

![图形界面](docs/gui.png)

* 14 个分类、2600+ 条掩码（压缩包 / 镜像 / 可执行 / 源代码 / 文档 / 音视频 / 图片 / 字体 / 临时文件 …），浅色 + 深色主题两套配色
* 内置 `scan` 命令：扫描你磁盘上真实的文件扩展名，自动查漏并把新类型归类写入规则包（无法归类的进“其他·待归类”）
* 图形界面 + 命令行两种用法，一键写入 DC 配置，自动备份、可一键卸载/还原
* 直接使用 DC 原生“文件类型颜色”机制（选项 → 颜色 → 文件类型颜色），安装后同样可以在 DC 里手工微调

> **免 Python 一键安装包**：Releases 中的 `dcmd-filetypes-highlight-<版本>.zip` 是现成分发包（exe 内置 Python 运行时，
> 支持 Win7 SP1 / 8 / 10 / 11 64 位与 DC 1.0.x / 1.1.x），解压后双击 `install.cmd` 即可；详细说明见包内 `README.md`。
> 本 README 其余内容以源码用法（`python dcmd_hl.py ...`）为主，打包版等价命令是 `dcmd_hl_cli.exe ...` / `dcmd_hl_gui.exe`。
> 打包方式：Python 3.8.10 + PyInstaller 4.10，`--onefile`（CLI 用 `--console`、GUI 用 `--windowed`），脚本见 `packaging/build.ps1`。

## 一、为什么不是传统插件？

Double Commander 的插件体系（`sdk/` 目录下的接口）共有 5 类，**都不能给面板中的文件名重新着色**：

| 插件类型 | 用途 | 能否改文件名颜色 |
| --- | --- | --- |
| WCX | 压缩包 | 否 |
| WDX | 文件内容字段 | 否 |
| WFX | 虚拟文件系统 | 否 |
| WLX | 查看器 | 否（只负责查看器窗口） |
| DSX | 搜索 | 否 |

面板里文件名的颜色由 DC 内部的 `TColorExt`（源码 `src/ucolorext.pas`）决定：
它在**打开面板时**根据 DC 设置里的“文件类型颜色”规则（`GetColorBy()`），把颜色填充到 `TFile.TextColor` 上。
插件 API 没有任何入口能参与这个过程。

因此本扩展包走的是与 DC 设置对话框（`src/frames/foptionsfiletypescolors.pas`）完全相同的路线：
**把规则写进 DC 自己的配置文件**。效果、兼容性、可撤销性与手工在 DC 选项里逐条添加颜色完全一致。

## 二、兼容性

| DC 版本 | 颜色存储位置 | 本工具 |
| --- | --- | --- |
| 1.1.x（含 1.1.32，已实测） | `<配置目录>\colors.json` 中的 `FileColors` 数组 | 默认（`--mode auto`/`json`） |
| 1.0.x 及更早 | `<配置目录>\doublecmd.xml` 中 `<Colors><FileFilters>` | `--mode xml` |

* 配置目录**自动探测**：显式指定（`-c` / `--exe` / 位置参数）→ 运行中的 `doublecmd.exe` 进程 → **解压目录附近**（父目录、`*doublecmd*` 子目录）→ 上次安装记录 → 常见安装位置 → `%APPDATA%\doublecmd` → 环境变量 `DC_CONFIG_PATH`。
* 给 DC **程序目录** / **`settings` 目录** / **`doublecmd.exe` 路径**都会自动识别：程序目录会优先取 `<程序目录>\settings`（便携模式，判断标志 `doublecmd.inf`），没有 `settings` 时回退到 `%APPDATA%\doublecmd`（安装版）。
* 运行环境：Windows + Python 3.8 以上（自带 tkinter 即可，无需安装任何第三方库）。macOS/Linux 的探测路径也已实现，但未实机验证。

## 三、快速开始

> ⚠️ **先退出 Double Commander**。DC 退出时会把自己内存里的设置写回配置文件，运行中改文件不但不生效，还会被覆盖；本工具检测到 DC 在运行时会拒绝写入（见第五节）。

**方式 A：图形界面（推荐）**

1. 双击 `filetypes-highlight\dcmd_hl_gui.cmd`
2. 顶部确认“配置目录”正确；左侧列表中取消勾选不想要的分类
3. 点右下角 **安装 / 更新到 Double Commander**
4. 重新启动 DC —— 文件面板里的文件名就会按类型着色

**方式 B：命令行**

```bat
cd filetypes-highlight

python dcmd_hl.py detect            :: 探测 DC 配置目录
python dcmd_hl.py detect "D:\Tools\doublecmd"        :: 直接给 DC 程序目录 / settings / doublecmd.exe 也行
python dcmd_hl.py install --dry-run :: 试运行，只显示将要做什么
python dcmd_hl.py install           :: 写入 DC 配置（自动备份）
python dcmd_hl.py install "D:\Tools\doublecmd"       :: 便携版：拖拽程序目录到命令行即可

:: 只要其中一部分分类（--only / --except 都可以用 id 或中文名）
python dcmd_hl.py install --only archives,images,audio
python dcmd_hl.py install --except temp,fonts

python dcmd_hl.py uninstall         :: 移除本工具写入的规则
python dcmd_hl.py preview --open    :: 生成 HTML 预览（浅色+深色）并打开
python dcmd_hl.py menu              :: 交互式中文菜单（等价于双击 dcmd_hl_cli.cmd）

:: 扫描扩展名查漏补缺（例如你收藏/工作目录），自动归类后写回规则包并安装
python dcmd_hl.py scan D:\Media C:\Users\you --top 60
python dcmd_hl.py scan D:\Media --apply --install
```

双击 `filetypes-highlight\dcmd_hl_cli.cmd` 会打开一个中文菜单，包含以上全部操作（第 7 项就是扩展名扫描/补全）。

### 扩展名扫描：让所有文件类型都有颜色

```bat
python dcmd_hl.py scan D:\工作 E:\下载          :: 只出报告：列出未覆盖的扩展名及归类建议
python dcmd_hl.py scan D:\Media --top 300       :: 多显示一些未覆盖项
python dcmd_hl.py scan D:\Media --apply         :: 把新扩展名归类写回规则包（自动备份规则包）
python dcmd_hl.py scan D:\Media --apply --install  :: 再顺手安装到 DC 配置
```

* 只枚举**文件名**，不读文件内容，42 万个文件约 3 秒；自动跳过 `node_modules`、`.git`、Windows/Program Files、AppData、系统卷目录等
* 归类顺序：**扩展名对照表**（内置数百个已知格式）→ 读每个未知扩展名抽样文件的**头部特征**（PE/ZIP/PDF/PNG/MP3/Matroska… 魔数，RIFF、ftyp 容器、tar、SQLite、文本侧写等）→ 仍认不出就进「其他·待归类」（醒目色，方便你日后在 GUI 里把它挪到合适分类）
* `--min-count N` 只收录出现次数 ≥ N 的扩展名；纯数字“扩展名”（日期戳产物）不会建规则
* 写入规则包前自动备份 `default_rules.json.fth-backup-<时间戳>`，可随时还原

## 四、规则包内容

规则按列表顺序匹配，**第一个命中的规则生效**（与 DC/TC 行为一致）。

| id | 名称 | 掩码数 | 浅色主题 | 深色主题 |
| --- | --- | ---: | --- | --- |
| `temp` | 临时·备份·产物 | 40 | `#7F7F7F` | `#A8A8A8` |
| `archives` | 压缩包·软件包 | 83 | `#0047CC` | `#82B1FF` |
| `diskimages` | 磁盘·光盘镜像 | 25 | `#00838F` | `#4DD0E1` |
| `executables` | 可执行·库文件 | 47 | `#C62828` | `#FF7A7A` |
| `scripts` | 脚本·快捷方式 | 38 | `#7B4B00` | `#D7A86E` |
| `code` | 源代码·网页 | 216 | `#3949AB` | `#9FA8FF` |
| `documents` | 文档·电子书 | 87 | `#1B7F1B` | `#7CD87C` |
| `spreadsheets` | 表格 | 20 | `#00796B` | `#66D9C8` |
| `audio` | 音频 | 49 | `#C07500` | `#FFC46B` |
| `video` | 视频·字幕 | 49 | `#7B1FA2` | `#C79BFF` |
| `images` | 图片 | 100 | `#B4007B` | `#FF7BD5` |
| `fonts` | 字体 | 25 | `#6B7A00` | `#C9D86B` |
| `configs` | 配置·数据 | 218 | `#546E7A` | `#9FB8C4` |
| `other` | 其他·待归类 | 1691 | `#C2185B` | `#FF80AB` |

> 上表是**扫描补全后**的当前状态：前 13 类是手工策展的基础分类（538 条掩码，覆盖常见格式）；
> `other`（其他·待归类）由 `scan` 自动维护——凡是暂时认不出归属、但在你的磁盘上真实出现的扩展名都会进这里，
> 保证“所有文件类型都有高亮”；确认格式后可以在 GUI 里把掩码挪到更合适的分类。

在 GUI 里改完点“保存规则文件…”即可写回 `rules/default_rules.json`；
也可以任意指定规则包：`--rules D:\my_rules.json`（格式见下）。

> 提示：`.ts` 常见于前端 TypeScript（已归入“源代码·网页”）也可能指视频容器 MPEG-TS；
> 如需改归“视频·字幕”，编辑 `rules/default_rules.json` 挪动对应掩码即可。

### 规则文件格式

```json
{
  "version": 1,
  "rules": [
    {
      "id": "images",
      "name": "图片",
      "enabled": true,
      "masks": ["*.jpg", "*.png", "*.psd"],
      "light": "#B4007B",
      "dark": "#FF7BD5",
      "examples": ["photo.jpg"],
      "comment": "图片文件（品红）"
    }
  ]
}
```

* `masks`：DC 掩码语法，支持 `*`、`?`、分号分隔的多个值，也支持 `>` 开头的 DC 搜索模板（高级用法，见下）
* `light` / `dark`：DC 1.1 的“文件类型颜色”支持浅色/深色两套主题颜色，DC 会按当前界面主题自动取用
* `enabled: false` 的分类不会安装

## 五、安装行为与安全网

* **自动备份**：每次写入前备份为 `<原文件>.fth-backup-20261018-093000`（同秒冲突自动加序号）
* **安装记录**：`filetypes-highlight\installed.json` 记录每个配置目录装了哪些规则
  （工具目录只读时，可用环境变量 `DCMD_HL_STATE_DIR` 把记录改到其它目录）
* **合并策略（不会动你自己的规则）**：
  * 同名规则 → 原地更新（DC 里手工改过的同名规则也会被覆盖，请换个名字）
  * 上次装过、这次没选的分类 → 自动移除
  * 你自己的其它规则 → 原样保留
  * 默认**追加到列表末尾**（优先级最低）；加 `--prepend` 则插到最前面（优先级最高，可盖过你已有的规则）
* **卸载**：`python dcmd_hl.py uninstall` 只删“本工具拥有”的规则名（安装记录 ∪ 当前规则包），其余规则和顺序不受影响
* **整文件还原**：`python dcmd_hl.py backups` 列出备份，`python dcmd_hl.py restore <备份文件> -y` 还原

## 六、在 DC 里手工查看与调整

安装后打开 DC：**配置 → 选项 → 颜色 → 文件类型颜色**，可以看到并且继续编辑这些规则：

* **名称**：只用于识别，不参与匹配
* **掩码**：如 `*.jpg;*.png`，见 DC 帮助；`>` 开头表示使用“搜索模板”语法（可匹配很复杂的条件，但注意那是 DC 扩展语法）
* **颜色**：文件名文字颜色（图标、背景不受影响）；DC 1.1 里分浅色/深色两套
* **属性**：留空表示**不匹配目录**；想只给“隐藏”或“只读”文件上色才填
* **顺序**：列表从上到下即匹配优先级，上方规则优先

## 七、常见问题

**装完颜色没变化？**
重启 DC（配置文件在启动/退出时读写）；确认修改的是 DC 实际使用的配置目录（`dcmd_hl.py detect` 会打印探测来源）；确认规则没有被你自己的同名规则挡住（工具默认把规则追加在末尾）。

**为什么不让我在 DC 运行时安装？**
DC 退出时会把内存中的全部设置写回 `colors.json` / `doublecmd.xml`，覆盖你的修改；运行中改文件也不会即时生效。确实要强行写入可以用 `--force`（不建议）。

**控制台里中文乱码？**
真实控制台正常显示；把输出重定向/管道（如 `| more`）时以 UTF-8 输出，请确保查看端按 UTF-8 解码。工具已尽力做编码保护。

**会不会破坏我的 DC 配置？**
每次写入都先自动备份；写入采用“同目录临时文件 + 原子替换”；JSON 解析器支持 DC 使用的宽松 JSON（未加引号的键、`//` 注释等），除了 `FileColors` 之外的所有设置原样保留。测试中用真实 DC 1.1.32 配置文件做过往返验证。

**只想手工加几条？**
不需要本工具：直接在 DC 选项里添加，或者 `python dcmd_hl.py export --format json -o snippet.txt` 生成配置片段自行粘贴。

## 九、说明

* 本扩展包不修改 DC 源码，也不参与 DC 的构建；它只是“规则包 + 配置写入器”，遵循 DC 原生设置格式。
* 规则包的掩码与配色可按需任意修改、再分发。
